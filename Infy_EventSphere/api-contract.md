# REST API Contract Specification: Infy_EventSphere

## 1. API Overview
This document specifies the RESTful API contracts across the 8 microservices constituting the Infy_EventSphere platform.

- **Base Protocol**: HTTP/1.1 over TLS (HTTPS).
- **Default Media Type**: `application/json;charset=UTF-8`.
- **Base URI Path**: `/api/v1/...` (Routed via the API Gateway on port `8080`).
- **Date-Time Format**: ISO-8601 UTC (`YYYY-MM-DD'T'HH:mm:ss'Z'`).

---

## 2. Authentication & Header Assumptions
Client requests passing through the API Gateway must supply or will have propagated the following contextual headers:

| Header Name | Type | Required | Description |
|---|---|---|---|
| `X-User-Id` | String | Yes | Unique identifier of the authenticated user (e.g., `usr_dev101`, `org_smith`). |
| `X-User-Role` | String | Yes | Authorized role: `ROLE_ADMIN`, `ROLE_ORGANIZER`, `ROLE_PARTICIPANT`. |
| `X-User-Department` | String | Yes | Department code/name (e.g., `Engineering`, `Sales`, `HR`). |
| `X-Correlation-Id` | String | Optional | UUID for distributed request tracing; auto-generated by Gateway if absent. |

---

## 3. Standardized Error Response Contract
All error responses from any microservice return the following unified JSON body:

```json
{
  "timestamp": "2026-10-28T08:00:00Z",
  "status": 409,
  "error": "Conflict",
  "errorCode": "DUPLICATE_REGISTRATION",
  "message": "Participant has already registered for this event.",
  "path": "/api/v1/registrations",
  "validationErrors": []
}
```

When input validation fails (`400 Bad Request`), `validationErrors` contains field-specific violations:
```json
{
  "timestamp": "2026-10-28T08:00:00Z",
  "status": 400,
  "error": "Bad Request",
  "errorCode": "VALIDATION_FAILED",
  "message": "Input validation failed for 2 fields.",
  "path": "/api/v1/events",
  "validationErrors": [
    { "field": "title", "rejectedValue": "", "message": "Event title is mandatory." },
    { "field": "startTime", "rejectedValue": "2020-01-01T10:00:00Z", "message": "Start time must be in the future." }
  ]
}
```

---

## 4. Pagination & Filtering Parameters
For list endpoints, pagination and filtering follow standard query parameters:
- `page`: Zero-indexed page number (default: `0`).
- `size`: Items per page (default: `20`, maximum: `100`).
- `sort`: Sort property and direction, e.g., `startTime,asc` or `createdAt,desc`.
- Filter parameters: `status`, `eventType`, `department`.

**Paginated Response Wrapper Schema (`PageResponse<T>`)**:
```json
{
  "content": [ ... ],
  "pageNumber": 0,
  "pageSize": 20,
  "totalElements": 45,
  "totalPages": 3,
  "isLast": false
}
```

## 5. Microservice Endpoint Catalog & DTO Contracts

### 5.1 `event-service` (Port: 8081 / Gateway Route: `/api/v1/events/**`)

#### 5.1.1 Create Event Draft
- **Endpoint**: `POST /api/v1/events`
- **Authorized Role**: `ROLE_ORGANIZER`
- **Request DTO (`CreateEventRequest`)**:
  ```json
  {
    "title": "Cloud Architecture Summit 2026",
    "description": "Comprehensive summit covering microservices and cloud scalability.",
    "eventType": "CORPORATE",
    "startTime": "2026-11-10T09:00:00Z",
    "endTime": "2026-11-10T17:00:00Z",
    "venueId": 1,
    "roomId": 1,
    "eligibleDepartment": "Engineering",
    "maxCapacity": 150
  }
  ```
- **Validation**:
  - `title`: `@NotBlank`, `@Size(min=3, max=100)`
  - `description`: `@NotBlank`, `@Size(min=10, max=1000)`
  - `eventType`: `@NotNull`, must match `EventType` enum
  - `startTime`: `@NotNull`, `@Future`
  - `endTime`: `@NotNull` (must be after `startTime`)
  - `maxCapacity`: `@NotNull`, `@Min(1)`
- **Response**: `201 Created`
  - **Response DTO (`EventDetailResponse`)**:
    ```json
    {
      "id": 1,
      "title": "Cloud Architecture Summit 2026",
      "description": "Comprehensive summit covering microservices and cloud scalability.",
      "eventType": "CORPORATE",
      "status": "DRAFT",
      "startTime": "2026-11-10T09:00:00Z",
      "endTime": "2026-11-10T17:00:00Z",
      "venueId": 1,
      "roomId": 1,
      "eligibleDepartment": "Engineering",
      "maxCapacity": 150,
      "createdBy": "org_smith",
      "createdAt": "2026-10-28T08:00:00Z"
    }
    ```

#### 5.1.2 Submit Event for Review
- **Endpoint**: `POST /api/v1/events/{id}/submit`
- **Authorized Role**: `ROLE_ORGANIZER` (Must be creator)
- **Response**: `200 OK` (Returns `EventDetailResponse` with `status: "PENDING_APPROVAL"`)

#### 5.1.3 Administrative Approval
- **Endpoint**: `POST /api/v1/events/{id}/approve`
- **Authorized Role**: `ROLE_ADMIN`
- **Request DTO (`ApprovalRequest`)**:
  ```json
  {
    "decision": "APPROVED",
    "remarks": "Compliant with Q4 engineering training policy."
  }
  ```
- **Response**: `200 OK` (Returns `EventDetailResponse` with `status: "APPROVED"`)

#### 5.1.4 Administrative Rejection
- **Endpoint**: `POST /api/v1/events/{id}/reject`
- **Authorized Role**: `ROLE_ADMIN`
- **Request DTO (`ApprovalRequest`)**:
  ```json
  {
    "decision": "REJECTED",
    "remarks": "Room capacity conflicts with anticipated attendance."
  }
  ```
- **Response**: `200 OK` (Returns `EventDetailResponse` with `status: "DRAFT"`)

#### 5.1.5 Publish Event
- **Endpoint**: `POST /api/v1/events/{id}/publish`
- **Authorized Role**: `ROLE_ORGANIZER` / `ROLE_ADMIN`
- **Response**: `200 OK` (Returns `EventDetailResponse` with `status: "PUBLISHED"`)

#### 5.1.6 List Published Events (Catalog Discovery)
- **Endpoint**: `GET /api/v1/events?status=PUBLISHED&eventType=CORPORATE&page=0&size=20`
- **Authorized Role**: Any authenticated user
- **Response**: `200 OK` (`PageResponse<EventSummaryResponse>`)

#### 5.1.7 Get Event Details by ID
- **Endpoint**: `GET /api/v1/events/{id}`
- **Response**: `200 OK` (`EventDetailResponse`)

### 5.2 `venue-service` (Port: 8082 / Gateway Route: `/api/v1/venues/**`)

#### 5.2.1 Create Venue & Rooms
- **Endpoint**: `POST /api/v1/venues`
- **Authorized Role**: `ROLE_ADMIN`
- **Request DTO (`CreateVenueRequest`)**:
  ```json
  {
    "name": "Global Tech Campus - Block A",
    "address": "100 Innovation Way",
    "city": "Bengaluru"
  }
  ```
- **Response**: `201 Created` (`VenueResponse`)

#### 5.2.2 Add Room to Venue
- **Endpoint**: `POST /api/v1/venues/{venueId}/rooms`
- **Authorized Role**: `ROLE_ADMIN`
- **Request DTO (`CreateRoomRequest`)**:
  ```json
  {
    "roomNumber": "Auditorium Alpha",
    "maxSeatingCapacity": 200,
    "amenities": "Dual 4K Projectors, Stage AV"
  }
  ```
- **Response**: `201 Created` (`RoomResponse`)

#### 5.2.3 Reserve Venue Slot (Collision Check)
- **Endpoint**: `POST /api/v1/venues/bookings`
- **Authorized Role**: `ROLE_ORGANIZER`, `ROLE_ADMIN`
- **Request DTO (`CreateBookingRequest`)**:
  ```json
  {
    "venueId": 1,
    "roomId": 1,
    "eventId": 1,
    "startTime": "2026-11-10T09:00:00Z",
    "endTime": "2026-11-10T17:00:00Z"
  }
  ```
- **Response**: `201 Created` (`BookingResponse`) or `409 Conflict` (`VENUE_SCHEDULE_CONFLICT`).

### 5.4 `registration-service` (Port: 8084 / Gateway Route: `/api/v1/registrations/**`)

#### 5.4.1 Register for Event
- **Endpoint**: `POST /api/v1/registrations`
- **Authorized Role**: `ROLE_PARTICIPANT`
- **Request DTO (`RegisterEventRequest`)**:
  ```json
  {
    "eventId": 1
  }
  ```
  *(Identity extracted automatically from `X-User-Id`, `X-User-Department`, and `X-User-Email`)*
- **Response**: `201 Created`
  - **Response DTO (`RegistrationResponse`)**:
    ```json
    {
      "registrationId": 1,
      "eventId": 1,
      "participantId": "usr_dev101",
      "status": "CONFIRMED",
      "registeredAt": "2026-10-28T08:00:00Z",
      "message": "Registration successfully confirmed."
    }
    ```
- **Error Codes**:
  - `409 Conflict`: `DUPLICATE_REGISTRATION`
  - `422 Unprocessable Entity`: `INELIGIBLE_PARTICIPANT`
  - `422 Unprocessable Entity`: `CAPACITY_EXCEEDED`

#### 5.4.2 Cancel Registration
- **Endpoint**: `POST /api/v1/registrations/{id}/cancel`
- **Authorized Role**: `ROLE_PARTICIPANT` (Must own registration)
- **Response**: `200 OK` (`RegistrationResponse` with `status: "CANCELLED"`)

#### 5.4.3 List Registrations for Event
- **Endpoint**: `GET /api/v1/registrations/event/{eventId}`
- **Authorized Role**: `ROLE_ORGANIZER`, `ROLE_ADMIN`
- **Response**: `200 OK` (`List<RegistrationResponse>`)

### 5.6 `feedback-service` (Port: 8086 / Gateway Route: `/api/v1/feedback/**`)

#### 5.6.1 Submit Event Feedback
- **Endpoint**: `POST /api/v1/feedback`
- **Authorized Role**: `ROLE_PARTICIPANT`
- **Request DTO (`SubmitFeedbackRequest`)**:
  ```json
  {
    "eventId": 1,
    "rating": 5,
    "comments": "Superb hands-on examples and clear architectural guidance!"
  }
  ```
- **Validation**:
  - `rating`: `@NotNull`, `@Min(1)`, `@Max(5)`
  - `comments`: `@Size(max=500)`
- **Response**: `201 Created`
  - **Response DTO (`FeedbackResponse`)**:
    ```json
    {
      "feedbackId": 1,
      "eventId": 1,
      "participantId": "usr_dev101",
      "rating": 5,
      "comments": "Superb hands-on examples and clear architectural guidance!",
      "submittedAt": "2026-11-10T17:30:00Z"
    }
    ```
- **Error Codes**:
  - `422 Unprocessable Entity`: `FEEDBACK_NOT_ELIGIBLE` (If user did not attend or event not completed)
  - `409 Conflict`: `DUPLICATE_FEEDBACK`

#### 5.6.2 Get Feedback for Event
- **Endpoint**: `GET /api/v1/feedback/event/{eventId}`
- **Authorized Role**: `ROLE_ORGANIZER`, `ROLE_ADMIN`
- **Response**: `200 OK` (`List<FeedbackResponse>`)
